## 1. Clerk Authentication & User Identity

- **Type**: OAuth, Email/Password, JWT Session Management.
- **Client Library**: `@clerk/react` (providing `useUser()`, `useAuth()`, `<ClerkProvider />`).
- **Server Library**: `@clerk/express`, `@clerk/backend`.
- **Token Verification**:
  - Express routes use `clerkMiddleware()` and `requireAuth()` extracting `authUserId` via `getAuth(req)`.
  - WebSocket server performs token verification on initial handshake (`auth:ok`) via `verifyToken(token, { secretKey, authorizedParties })`.
- **Identity Enforcement**:
  - College email constraint (`^[a-z0-9]+(?:[._-][a-z0-9]+)+\\.cse@ghrietn.raisoni.net$`) or `ADMIN_EMAILS` checked in `requirePlatformAuth`.
- **Profile Synchronization**:
  - On login/sync (`/api/auth/me`, `/api/auth/sync`), if user is missing in `devcollective_profiles`, an initial record is created and populated from Clerk metadata.

## 2. Supabase (Database & Storage)

- **Type**: Managed PostgreSQL, PostgREST API, Object Storage.
- **Connection Methods**:
  1. `@supabase/supabase-js` service role admin client (`supabaseAdmin` in `server/supabase.ts`) with `SUPABASE_SECRET_KEY` for administrative operations.
  2. Direct REST / RPC calls via `fetch` with apikey and Authorization bearer header in `server/learningProgress.ts`.
  3. Client-side Supabase client using public anon key for direct queries where appropriate.
- **Key Tables**:
  - `devcollective_profiles`: Core user profile, role, REP points, level, college, branch, bio, skills.
  - `devcollective_posts`: Community posts and discussions across categories.
  - `devcollective_post_likes`: Like tracking per user and post.
  - `devcollective_conversations` & `devcollective_conversation_members`: 1-to-1 chat threads and membership.
  - `devcollective_messages`: Chat messages with delivery, read receipts, replies, and edits.
  - `devcollective_message_reactions`, `devcollective_message_stars`, `devcollective_message_pins`: Chat rich features.
  - `devcollective_user_presence`: Last seen timestamps and online status tracking.
  - `devcollective_user_blocks`, `devcollective_user_reports`, `devcollective_conversation_mutes`, `devcollective_conversation_archives`, `devcollective_conversation_hides`: Safety & moderation.
  - `learning_modules`, `learning_submodules`, `user_submodule_progress`, `user_module_progress`, `user_level_progress`: Level 0 learning tree.
- **Stored Procedures (RPC)**:
  - `complete_learning_submodule(p_user_id, p_submodule_id)`: Atomic learning verification and REP award.
- **Object Storage**:
  - Bucket `mentor-resumes`: PDF resume uploads for mentor verification (up to 5MB).

## 3. Google Gemini Generative AI

- **SDK**: `@google/genai` (v2.17.1).
- **Model**: `gemini-3.6-flash`.
- **Use Cases**:
  1. **Roadmap Chat Mentor** (`/api/ai/roadmap-chat`):
     - Interactive conversational mentor that asks targeted questions about skill level, interests, and prior experience.
     - Function calling via declaration `finalize_roadmap` with structured JSON schema (`ROADMAP_JSON_SCHEMA`) generating levels, capstone projects, and learning resources.
  2. **Structured Resume Extraction** (`/api/resume/parse`):
     - Extracts text from uploaded PDF resumes using `pdf-parse`.
     - Analyzes text with Gemini returning validated JSON (`branch`, `academicYear`, `bio`, `skills`, `githubUrl`, `linkedinUrl`, `confidence`).

## 4. Local Python Embedding Service (`ai-service`)

- **Runtime**: Python FastAPI running on port 8000 (or configured port).
- **Model**: `BAAI/bge-m3` using `sentence-transformers`.
- **Endpoint**: `POST /embed` accepting `{"text": "..."}` and returning a 1024-dimensional vector embedding.
- **Purpose**: Semantic vector search, future mentor matching, and knowledge discovery.

---

## 5. WebSockets Real-Time Service

- **Engine**: `ws` (Node.js WebSocketServer).
- **Port**: Dedicated port (default 3001, dynamically bound to Render `PORT` in `ws-start.ts`).
- **Capabilities**:
  - Connection authentication via Clerk JWT.
  - Online presence broadcasting and heartbeat management.
  - 1-to-1 direct messaging with real-time delivery and read receipts (`delivered_at`, `read_at`).
  - Emoji reactions with live room broadcasts.
  - In-chat typing indicators (`typing:start`, `typing:stop`).
  - Live conversation updates and message pin/star events.
