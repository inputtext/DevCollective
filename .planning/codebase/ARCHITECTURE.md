## System Overview

DevCollective is an AI-powered college learning and developer collaboration platform built with a modern dual-process cloud architecture:

```
                                  ┌──────────────────────────┐
                                  │      Client Browser      │
                                  │   (React 19 + Tailwind)  │
                                  └─────────────┬────────────┘
                                                │
                     ┌──────────────────────────┴──────────────────────────┐
                     │ HTTPS Requests                                      │ WSS Connection
                     ▼                                                     ▼
      ┌─────────────────────────────┐                       ┌─────────────────────────────┐
      │     devcollective-app       │                       │      devcollective-ws       │
      │   (Express + Vite SPA)      │                       │     (ws Node.js Server)     │
      │  Port: 3000 / Dynamic PORT  │                       │  Port: 3001 / Dynamic PORT  │
      └──────┬───────────────┬──────┘                       └──────────────┬──────────────┘
             │               │                                             │
             │ Clerk Auth    │ GenAI SDK                                   │ Supabase Admin
             ▼               ▼                                             ▼
      ┌────────────┐  ┌─────────────┐                       ┌─────────────────────────────┐
      │ Clerk Auth │  │ Google      │                       │       Supabase Cloud        │
      │  Service   │  │ Gemini 3.6  │                       │ (Postgres DB, RLS, Storage) │
      └────────────┘  └─────────────┘                       └─────────────────────────────┘
```

## Core Components

### 1. Frontend Client (`src/`)
- **Technology**: React 19, TypeScript, Vite.
- **Styling**: Tailwind CSS v4, custom utility classes in `src/index.css`, glassmorphism, gradient badges, and dark/light system adaptation.
- **Animation Layer**: Framer Motion (`motion`), GSAP for staggered card reveals and smooth micro-interactions, Three.js canvas for dynamic background atmosphere.
- **Routing & State**:
  - `src/App.tsx` orchestrates page state, navigation bars, modals, authentication status checks, and onboarding redirections.
  - Pages in `src/pages/` encapsulate major domains: `LandingPage`, `DashboardPage`, `Level0Page`, `RoadmapPage`, `CommunityPage`, `EventsPage`, `MentorDirectoryPage`, `LeaderboardPage`, `StudentProfilePage`, `AdminPage`.
  - Shared context providers manage authentication sync and active conversation streams.

### 2. Primary API Server (`server.ts`, `server/`)
- **Technology**: Express 4, TypeScript via `tsx` (dev) and `esbuild` (prod).
- **Authentication**: `clerkMiddleware()` populates Clerk authentication session. `requireAuth` validates active sessions and injects `authUserId`.
- **Domain Sub-routers**:
  - `learningProgress.ts`: Manages Level 0 curriculum, module hierarchies, submodule verification, and REP reward attribution.
  - `adminRoutes.ts`: Enforces college email domain (`@ghrietn.raisoni.net`), verifies admin privileges, and handles mentor approval workflows.
  - Community & Profile endpoints: CRUD for posts, likes, profile updates, and mentor listings.
  - AI endpoints: `/api/ai/roadmap-chat` (conversational Gemini mentor) and `/api/resume/parse` (structured resume data extraction).

### 3. Real-Time Communication Server (`server/websocket.ts`, `ws-start.ts`)
- **Technology**: `ws` WebSocketServer over Node HTTP.
- **Lifecycle**:
  - Initial connection requires `auth` message containing Clerk JWT token within 8000ms.
  - In-memory presence map tracks active client connections per user ID and broadcasts changes.
  - Disconnect updates `devcollective_user_presence.last_seen_at` in Supabase.
- **Chat Operations**:
  - Direct 1-to-1 conversation creation with duplicate prevention.
  - Message send, edit, forward, reaction, and delete (for me / for everyone).
  - Pinned and starred message tracking.
  - In-memory delivery receipt dispatching when recipient is actively online.

## Data Flow Sequences

### Authentication & Profile Onboarding Flow
1. User signs in on frontend via Clerk modal or OAuth.
2. React app initializes Clerk session and calls `POST /api/auth/sync` with user metadata.
3. Express server checks for existing profile in `devcollective_profiles` by `clerk_user_id`.
4. If missing, creates a default profile with base REP (0) and level (1).
5. If user has not completed onboarding, frontend routes to `ProfileSetupPage.tsx`.

### AI Roadmap Generation Flow
1. User opens `/roadmap` and begins conversational chat.
2. Client sends history and latest response to `POST /api/ai/roadmap-chat`.
3. Server submits dialogue history to Gemini 3.6 Flash with function calling declaration `finalize_roadmap`.
4. Gemini asks clarifying questions until sufficient background is gathered.
5. When ready, Gemini triggers `finalize_roadmap`, and the server returns the structured roadmap levels, capstones, and resources to the client for interactive exploration.

### Gamification & Reputation (REP) Flow
1. User completes learning submodules or contributes high-value community posts.
2. Learning verification triggers Supabase RPC `complete_learning_submodule`.
3. Database atomically increments user REP and recalculates level (`level = Math.floor(rep / 150) + 1`).
4. Leaderboards query `devcollective_profiles` ordered by `rep DESC` filtered by college or branch.
