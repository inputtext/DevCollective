# Codebase Conventions & Standards

> Generated by `/gsd-onboard` codebase mapping.
> Evidence sources: `src/`, `server/`, `server.ts`, `PROJECT_RULES.md`, `GSD-STYLE.md`.

## Language & File Conventions

### 1. Naming Standards
- **React Components & Pages**: `PascalCase.tsx` (e.g. `RoadmapPage.tsx`, `MentorDirectoryPage.tsx`, `Navbar.tsx`).
- **Server Route Modules & Utilities**: `camelCase.ts` (e.g. `adminRoutes.ts`, `learningProgress.ts`, `supabase.ts`).
- **Hooks**: `useCamelCase.ts` (e.g. `useWebSocket.ts`, `useAuth.ts`).
- **Types & Interfaces**: Declared in `src/types.ts` using `PascalCase` interface and type aliases (e.g. `UserProfile`, `Roadmap`, `LevelProgress`).
- **Database Tables & Fields**: `snake_case` in PostgreSQL (e.g. `clerk_user_id`, `streak_days`, `academic_year`), mapped to `camelCase` on API serialization via converter functions (e.g. `toUserProfile()`, `toMentorProfile()`).

## Architecture & Code Organization Patterns

### 1. Data Conversion Layer
- Database models returned by Supabase are never exposed raw to the client if they contain private or internal fields.
- Conversion functions like `toUserProfile(row)` and `toMentorProfile(row)` normalize database snake_case keys into TypeScript camelCase models and set safe default values.

### 2. Authentication & Authorization
- Every authenticated API endpoint uses `requireAuth` to verify the Clerk session token.
- Protected platform actions (e.g. campus-only access) verify email domains via `requirePlatformAuth`.
- Admin-only routes verify user roles or `ADMIN_EMAILS` via `requireAdmin`.

### 3. Error Handling
- **API Responses**: Always return JSON with an explicit `error` key upon failure:
  ```json
  { "error": "Descriptive message for UI or client logging" }
  ```
- **AI Resilience**: All Gemini interactions are wrapped in `try/catch` and run through `friendlyAiError(err)` to present actionable guidance to students (handling rate limits, quota issues, and temporary downtime gracefully).

## Styling & Design Tokens

- **CSS Framework**: Tailwind CSS v4 via `@tailwindcss/vite`.
- **Aesthetic**: Premium dark-mode-first aesthetic with rich glassmorphism (`backdrop-blur`), subtle borders (`border-white/10`), vibrant glow gradients, and animated badges.
- **Icons**: Standardized on `lucide-react`.
- **Category Themes**: Centralized in `src/community-category-theme.ts` for consistent colors across badges, filters, and cards.

## Git & GSD Commit Protocol

- One logical change per atomic commit.
- Conventional commit message format:
  ```
  feat(roadmap): add interactive level prerequisite checker
  fix(auth): normalize college email casing during validation
  docs(onboarding): update architecture and stack references
  ```
